    System Architecture¶

    OpsWarden is designed as a modular Hexagonal Monolith. All core domain logic, state authorization, and invariant enforcement reside within a single high-performance Rust process. Both Next.js web and Tauri desktop interfaces consume the same unified REST and WebSocket API contracts.

    Architectural Layers¶

    flowchart LR
    Handlers[handlers<br/>Axum REST & WebSocket] --> App[app<br/>Use Cases & Orchestration]
    App --> Ports[ports<br/>Traits & Interfaces]
    Ports --> Domain[domain<br/>Pure Business Invariants]
    Adapters[adapters<br/>PostgreSQL · Vault · Event Bus] -. Implement .-> Ports

    The system enforces strict inward dependency flow. Domain models contain zero external framework dependencies:

    Layer Path Responsibilities Invariants
    Domain server/src/domain/ Pure models, lifecycle state machines, domain events, stable error codes No HTTP, SQL, or transport dependencies
    Ports server/src/ports/ Trait definitions required by application use cases Pure Rust interfaces
    App server/src/app/ Authorization-aware use case orchestration Executes database transactions and emits events
    Adapters server/src/adapters/ PostgreSQL SQLx queries, Tokio event bus, AES-GCM credential vault Implements port traits; no business policy
    Handlers server/src/handlers/ Axum REST routes, JSON serialization, WebSocket frame dispatch Thin transport mapping
    Client client-web/ UI components, local query caching, responsive rendering Never dictates server-side business rules

    End-to-End Execution Flow¶

    When a user triggers an operational action (e.g., acknowledging an incident or validating a release step), data flows through six distinct phases:

    1. HTTP Action: The client sends a signed bearer JWT request to an Axum endpoint.
    2. Handler Validation: Handlers parse parameters and extract caller identity from JWT headers.
    3. Use Case Execution: The application layer checks caller team capability (Observer, Responder, Manager).
    4. Database Transaction: SQLx executes the state mutation within an atomic PostgreSQL transaction.
    5. Event Emission: Upon commit, the use case publishes a DomainEvent to the in-memory Tokio broadcast channel.
    6. WebSocket Relay: The WebSocket edge filters and broadcasts JSON frames to all authorized team members in real-time.

    Code Base Organization¶

    opswarden/
├── server/                     # Rust backend process
│   ├── src/
│   │   ├── domain/             # Pure models & state rules
│   │   ├── ports/              # Trait definitions
│   │   ├── app/                # Application use cases
│   │   ├── adapters/           # Database & external providers
│   │   └── handlers/           # Axum HTTP & WebSocket routes
│   └── migrations/             # Versioned PostgreSQL migrations
├── client-web/                 # Next.js web application
├── client-desktop/             # Tauri desktop wrapper
├── contracts/                  # Shared role capabilities JSON
└── docs/                       # Architectural Decision Records (ADRs)
