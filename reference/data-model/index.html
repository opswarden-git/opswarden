    Data model¶

    The versioned migrations in server/migrations/ are the executable source of truth. This view explains the relations a contributor needs before changing a use case. One diagram per domain: twenty tables in a single graph is a picture nobody can read.

    Identity and teams¶

    Membership is the only thing that grants a capability. A ban blocks a user from a team without erasing what they already wrote.

    erDiagram
    USERS ||--o{ TEAM_MEMBERS : joins
    TEAMS ||--o{ TEAM_MEMBERS : authorizes
    TEAMS ||--o{ TEAM_BANS : blocks

    Incidents and the timeline¶

    An incident belongs to one team and may be assigned to one user. Its timeline carries the conversation; its event log carries the audit trail.

    erDiagram
    TEAMS ||--o{ INCIDENTS : owns
    USERS o|--o{ INCIDENTS : assigned
    INCIDENTS ||--o{ TIMELINE_ENTRIES : records
    INCIDENTS ||--o{ INCIDENT_EVENTS : audits
    TIMELINE_ENTRIES ||--o{ TIMELINE_ENTRY_ATTACHMENTS : owns
    TIMELINE_ENTRIES ||--o{ TIMELINE_REACTIONS : receives

    Releases¶

    A release sequences ordered steps. Linking an active incident is what derives its blocked state, so the link table is the join both sides read.

    erDiagram
    TEAMS ||--o{ RELEASES : owns
    RELEASES ||--|{ RELEASE_STEPS : sequences
    RELEASES ||--o{ RELEASE_INCIDENTS : links
    INCIDENTS ||--o{ RELEASE_INCIDENTS : blocks

    Direct messages¶

    The same attachment and reaction grammar as the timeline, on a conversation scoped to two users instead of a team.

    erDiagram
    USERS ||--o{ PRIVATE_MESSAGES : sends
    USERS ||--o{ PRIVATE_MESSAGES : receives
    PRIVATE_MESSAGES ||--o{ PRIVATE_MESSAGE_ATTACHMENTS : owns
    PRIVATE_MESSAGES ||--o{ PRIVATE_MESSAGE_REACTIONS : receives

    Integrations and automations¶

    A connection holds its secrets apart from its displayable metadata. A webhook delivery is the idempotency key; a run is what a rule did with it.

    erDiagram
    TEAMS ||--o{ SERVICE_CONNECTIONS : configures
    SERVICE_CONNECTIONS ||--o{ SERVICE_CONNECTION_SECRETS : protects
    SERVICE_CONNECTIONS ||--o{ WEBHOOK_DELIVERIES : authenticates
    TEAMS ||--o{ AUTOMATION_RULES : owns
    WEBHOOK_DELIVERIES ||--o{ AUTOMATION_RUNS : triggers
    AUTOMATION_RULES o|--o{ AUTOMATION_RUNS : evaluates

    Invariants worth protecting¶

    • A partial unique index permits exactly one Manager per Team.
    • Kicks and bans do not rewrite historical authors or actors.
    • Release steps remain ordered; linked active incidents derive the blocked state.
    • Connection secrets are encrypted separately from displayable metadata.
    • Webhook delivery identifiers and automation runs preserve idempotency and audit history.
    • Revoked JWT identifiers persist logout invalidation.
    • Conversation attachments inherit the authorization and deletion boundary of their parent message and are served through authenticated download routes.

    When a migration changes one of these rules, update the domain invariant, its integration tests and this page in the same pull request.
