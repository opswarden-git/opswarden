OpsWarden `v1.0.11` reintroduces Alertmanager from the clean corrective
`v1.0.10` baseline and adds repository controls that prevent the failure mode
which caused the earlier rollback.

### Alertmanager

- Managers can configure a team-scoped Alertmanager bearer token encrypted at
  rest.
- `POST /webhooks/alertmanager/{connection_id}` accepts bounded JSON
  notification groups and triggers `alert_firing` rules.
- Exact retries are durably deduplicated.
- Resolved groups are accepted and durably ignored without creating incidents.
- Only allowlisted normalized values reach filters and templates; arbitrary
  labels, annotations and secrets do not.
- Alertmanager appears in onboarding without replacing the six existing
  integration previews.

See the [operator guide](../integrations/alertmanager.md) and the
[current contract](../adr/0001-alertmanager-webhook-contract.md).

### Delivery guardrails

- `main` requires an up-to-date `CI · Required gate` through pull requests.
- New source and test files are capped at 500 lines and oversized legacy files
  cannot grow.
- Unsafe TypeScript bypasses and unrelated test deletion fail CI.
- The automation catalog contract names all eight services explicitly.

The release passed backend and frontend validation, the release E2E, native
Windows/macOS/Linux packaging, and attested server and self-hosted web image
publication.
