    Getting Started¶

    This guide walks you through setting up and running OpsWarden on your local machine using Docker Compose or native development tools.

    Prerequisites¶

    Ensure you have the following tools installed:

    Tool Version / Requirement Purpose
    Docker & Docker Compose 20.10+ / Compose v2 Complete stack execution (Database, Backend, Web, Desktop packager)
    Rust Current stable toolchain Native backend development (server)
    Node.js & npm Node 24 Web client and tooling (client-web)
    Tauri Prerequisites System C compiler & webkit2gtk Desktop application development (client-desktop)

    Quick Start (Docker Compose)¶

    Clone the repository and launch the full operational stack:

    git clone https://github.com/opswarden-git/opswarden.git
cd opswarden
cp .env.example .env
docker compose up --build

    Compose provisions and links four core services:

    Service Endpoint Description
    Web Client http://localhost:8081 Next.js web application (/en and /fr)
    Backend API http://localhost:8080 Rust Axum REST and WebSocket server
    PostgreSQL localhost:5433 Relational database engine
    Desktop Artifacts ./artifacts/ Compiled Linux AppImage and DEB packages

    Verifying Local Health¶

    After starting the stack, verify that each layer is responsive:

    # Check Rust API health
curl http://localhost:8080/health

# Check localized automation catalog & server metadata
curl http://localhost:8080/about.json

# Check Web Application accessibility
curl http://localhost:8081/en

    Local Component Development¶

    1. Backend Server¶

    cargo run --bin opswarden-server             # Start API server on http://localhost:8080
cargo test --workspace                       # Execute Rust unit and integration tests
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo fmt --all -- --check

    2. Web Application¶

    # Run commands from the repository root
npm ci
npm run dev --workspace client-web           # Start dev server on http://localhost:4242
npm run build --workspace client-web         # Build production web bundle
npm run typecheck --workspace client-web     # TypeScript verification
npm run test:coverage --workspace client-web # Vitest test suite and coverage

    3. Desktop Application¶

    just desktop-dev                             # Start Tauri application in URL dev mode

    Quality & Test Gates¶

    The project enforces quality and coverage thresholds before a pull request is squash-merged:

    • Rust Backend: Tarpaulin source-line coverage must reach 70%.
    • Web Frontend: Vitest requires 70% lines, 65% statements/functions, and 55% branches across production sources.
    • Browser journeys: Playwright runs the complete Manager, Responder, and Observer suite against the Compose stack.
    • Static gates: ESLint, Stylelint, TypeScript, Prettier, Knip normal/production, Actionlint, Zizmor, ShellCheck, Cargo Clippy, Audit, and Deny.

    Run the pull-request gate locally with just ci. The slower coverage and native desktop packaging gates are available through just ci-full.

    For detailed contribution workflows and Definition of Done, consult the Contributing Guide. Identity OAuth, Team integrations, and the deterministic single-Team dataset are documented in Integrations and demo.
